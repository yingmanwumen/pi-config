# Spec to Implementation

Use this workflow to turn a Notion PRD or feature spec into an implementation plan, linked tasks, and progress tracking.

1. Search for the spec and ask the user to choose if multiple candidates match.
2. Fetch the spec and extract requirements, acceptance criteria, constraints, priorities, dependencies, and ambiguities.
3. Record assumptions and clarifications before creating artifacts.
4. Choose a quick plan for a small change or a phased plan for a migration or larger feature.
5. Fetch the plan and task database schemas before writing. Use explicit parent IDs and valid property names.
6. Create the plan, then create right-sized tasks with objective, acceptance criteria, dependencies, resources, and relations to the spec and plan.
7. Optionally add a short implementation section back to the spec only with user authorization.
8. Re-fetch created pages, report links and statuses, and define the cadence for future progress updates.

Keep tasks small enough to complete in roughly one or two days when practical. Do not invent assignees, due dates, priorities, or database properties.
